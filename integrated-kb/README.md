# Корпоративная база знаний

Веб-приложение для корпоративной базы знаний, управления
документами, компетенциями, тестированием и видеоматериалами.

## Технологии

- Python 3.12, WSGI, Gunicorn
- PostgreSQL 16
- HTML, CSS, JavaScript
- Docker и Docker Compose
- Nginx для HTTPS

## Структура проекта

- `app/` — серверная логика
- `static/` — пользовательский интерфейс
- `sql/` — схема базы данных и SQL-скрипты
- `deploy/` — конфигурации и инструменты развёртывания
- `tests/` — автоматизированные тесты
- `compose.yaml` — Docker Compose
- `.env.example` — шаблон переменных окружения

## Быстрый старт

### 1. Получение исходников

```bash
git clone https://github.com/Floressino/kb.git
cd kb
```

### 2. Настройка окружения

```bash
cp .env.example .env
```

Измените `DB_PASSWORD` на собственный длинный случайный пароль.

Не публикуйте `.env`. При использовании текущего
`DATABASE_URL` пароль должен быть совместим с форматом URL.

### 3. TLS-сертификаты

Для HTTPS необходимы файлы:

- `tls/cert.pem`
- `tls/key.pem`

Они не входят в репозиторий.

Для локальной разработки можно создать самоподписанный сертификат:

```bash
mkdir -p tls

openssl req -x509 -newkey rsa:3072 -nodes \
  -keyout tls/key.pem \
  -out tls/cert.pem \
  -days 30 \
  -subj "/CN=localhost"

chmod 600 tls/key.pem
```

Самоподписанный сертификат предназначен только для
локальной разработки.

### 4. Запуск

```bash
docker compose up -d --build
```

На новой пустой базе PostgreSQL схема из
`sql/schema_production.sql` устанавливается автоматически.

**Важно:** автоматическая инициализация выполняется только
при первом создании пустого PostgreSQL volume.

SQL-файл не является механизмом миграции существующей базы.

### 5. Создание первого администратора

Скрипт `deploy/create_admin.py` позволяет интерактивно
создать администратора с собственными учётными данными.

Перед запуском необходимо убедиться, что роль `admin`
существует в таблице `roles`, а таблица `users` пуста.

Создание роли в новой пустой базе:

```bash
docker compose exec -T db \
  psql -U kb_prod -d kb_prod \
  -c "INSERT INTO roles(code,name)
      VALUES('admin','Администратор')
      ON CONFLICT(code) DO NOTHING"
```

Затем:

```bash
docker compose exec app \
  python -m deploy.create_admin
```

Пароль вводится интерактивно, без отображения в терминале.
Минимальная длина — 12 символов.

Не запускайте первоначальную настройку на существующей
production-базе.

### 6. Открытие приложения

При стандартных настройках `.env.example`:

https://localhost:8443

Браузер предупредит о самоподписанном сертификате.

По умолчанию HTTPS доступен только через `127.0.0.1`.

## Безопасность

- Настоящие пароли и токены не должны попадать в Git.
- TLS-ключи и пользовательские файлы не публикуются.
- В репозитории находится только структура PostgreSQL,
  без реальных пользовательских записей.
- Для публичного развёртывания необходим действительный
  TLS-сертификат и отдельная проверка безопасности.
- Не используйте демонстрационные скрипты на рабочей базе.

## Проверки

Проверка конфигурации:

```bash
docker compose config --quiet
```

Сборка приложения:

```bash
docker compose build app
```

## Дополнительная документация

Каталог `deploy/poc/` содержит исторические инструменты
локального демонстрационного стенда. Некоторые команды
используют прежнюю структуру проекта и требуют адаптации.

Для нового развёртывания используйте корневой `compose.yaml`.
