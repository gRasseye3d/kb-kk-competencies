# Переносимый локальный HTTPS PoC

Требуются Docker с Compose v2+, Python 3 и OpenSSL. Все команды запускаются
**из корня экспорта**, где соседствуют `kb/` и `docs/`. Не копируйте только `poc/`:
Compose `context: ../../..` и Dockerfile `COPY kb/...` требуют именно эту структуру.
Не используйте существующий production/демо volume; имя проекта `kb_kk_poc`
фиксировано также в `extend_demo.py`. При конфликте с другим проектом остановитесь.

```sh
sh kb/deploy/poc/local.sh prepare  # новый ignored .env и TLS, без перезаписи
sh kb/deploy/poc/local.sh build
sh kb/deploy/poc/local.sh schema   # ТОЛЬКО новая пустая БД; v4, затем 03–06
sh kb/deploy/poc/local.sh admin    # пароль вводится скрыто, логин demo_admin
sh kb/deploy/poc/local.sh start
```

Откройте `https://localhost:18575`, подтвердив локальный самоподписанный сертификат.
Cookie остаются Secure/HttpOnly/SameSite; `KB_DEV_HTTP_COOKIE` не требуется.
Не публикуйте этот порт, не подключайте туннель; доступ только через loopback.
Секреты, TLS, данные PostgreSQL не входят в Git. `.env.example` содержит только
шаблон: не применяйте его как действующую конфигурацию. Генератор использует hex,
поэтому пароль безопасно подставляется в PostgreSQL URI без URL-кодирования.
Не запускайте `docker compose config` без `--quiet` при действующем `.env`:
он может вывести подставленный секрет.

`schema` не является мигратором и не идемпотентен: повторно не запускайте;
после частичного сбоя исследуйте состояние отдельно. `admin` откажется работать
с непустой таблицей пользователей. `stop` сохраняет volume, удаление данных
автоматически не выполняется. Создавайте отдел, роли, пользователей и карту через
административный UI — см. `kb/README.md`. Для скриптового наполнения `seed.py`
принимает JSON с вашими новыми паролями через stdin; шаблона с живыми паролями нет.

## Дополнительные инструменты

- `bootstrap.py`: новый администратор в пустой v4 БД, пароль на stdin.
- `seed.py`: одноразовый **изменяющий данные** API seed; ожидает логины
  `demo_admin`, `demo_manager`, `demo_kk`, `demo_employee`, `smoke_employee` в JSON.
  Пароль администратора должен совпадать с выбранным при bootstrap; остальные
  создайте самостоятельно. Не запускайте seed повторно или на чужом стенде.
- `browser_smoke.py`: отдельный Playwright smoke; `--help` описывает параметры.
  По умолчанию не завершает назначения, но выполняет вход/выход (изменяет сессии).
  `--exercise-user` — только одноразовый новый smoke-пользователь.
- `extend_demo.py`: продвинутый изменяющий сценарий, см. [EXTEND_DEMO.md](EXTEND_DEMO.md).
- Seed/browser/extension допускают непроверенный TLS только для локального
  самоподписанного PoC. Никогда не применяйте их к публичному/боевому сервису.

Проверки в `VERIFICATION.md` не означают, что контейнеры, HTTPS, PostgreSQL или
браузер были запущены при упаковке. Образы тегированы, не закреплены digest:
структура сборки воспроизводима, но побайтовая воспроизводимость образов не обещается.
