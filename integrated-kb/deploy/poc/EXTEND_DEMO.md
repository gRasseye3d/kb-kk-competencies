# Добавочное наполнение отдельного локального PoC

Это не автоматический quickstart и не production-инструмент. Скрипт ожидает уже
выполненный одноразовый `seed.py`, DEMO-отдел, утверждённую активную карту и
учётные записи администратора, руководителя и ответственного КК.

По умолчанию корень вычисляется из расположения скрипта, адрес —
`https://localhost:18575`; при необходимости их явно задают `KB_DEMO_ROOT` и
`KB_DEMO_BASE`. Используются `.env`, фиксированный Compose-проект `kb_kk_poc`
и **ваш локальный** `demo-credentials.json` (права 0600, не symlink), где ключи
`demo_admin`, `demo_manager`, `demo_kk` соответствуют паролям этого стенда.
Секреты не включены в экспорт и не должны попадать в Git.

Только после ручной проверки правильности одноразового локального окружения
создайте пустой `.owner` в его корне как явный маркер разрешения. Затем оттуда:

```sh
python3 kb/deploy/poc/extend_demo.py --suffix localrun01
```

Скрипт создаёт новых сотрудников и отдельный smoke login, 6 компетенций,
12 вопросов, 3 теста, 10 неначатых назначений; новая версия карты архивирует
предыдущую. Фиксированные логины новых сотрудников не должны существовать.
Наличие нового suffix не разрешает повторно создавать тех же пользователей.
До записей делается приватный pg_dump и read-only снимок. Журнал намерения
записывается до HTTP-запроса; неоднозначный ответ блокирует повторную запись.
После сбоя не удаляйте lock/журнал без ручного расследования.

`demo-extension-*` содержит приватные снимки, хеши паролей, журналы и новые
пароли: каталог должен оставаться локальным, игнорируется Git. Не публикуйте
результаты и не заменяйте ими документы проекта. Проверка сохранности разрешает
только ожидаемую архивацию карты, исключая изменяемые sessions/login rate windows.

Safety-тесты не запускают API, Docker или БД:

```sh
cd kb
env -u DATABASE_URL PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s deploy/poc -p 'test_*.py' -v
```
