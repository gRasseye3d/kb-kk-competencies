# Промежуточный этап: ручной импорт ответа для выбранной статьи

Статус на 2026-11-10: **промежуточный ручной импорт проверен на частном dev-стенде** (адрес стенда предоставляется владельцем отдельно). Автоматическая генерация через LLM **не подключена**, кнопка «Сгенерировать» отключена. Не передавайте сюда конфиденциальные материалы или ответ модели без проверки человеком.

Ответственный КК выбирает опубликованную доступную ему статью своего отдела в поиске с серверной ACL-фильтрацией **до** пагинации. `GET /api/testing/imports/source-pages?q=...&limit=20&offset=0` возвращает `{ "items": [{ "id": "…", "title": "…", "space_name": "…", "current_revision_id": "…" }], "total": 1 }`. Закрытые, удалённые, черновые и чужие статьи не выдаются. Выбранная ревизия фиксируется; после изменения статьи создание/редактирование или одобрение привязанного импорта возвращает 409, автоматической перепривязки нет.

Оператор указывает `questions_count` (1–30), `answers_count` (2–8), темы (до 10) и вручную вставляет/загружает JSON-ответ `{ "questions": [{ "question": "…", "options": ["А", "Б"], "correct_answer": 0 }] }`. `correct_answer` — индекс с нуля; неверный индекс не исправляется догадкой. `POST /api/testing/imports/from-generated` принимает `{ "source_page_id": "UUID статьи", "source_revision_id": "UUID ревизии", "settings": { "questions_count": 3, "answers_count": 4, "topics": ["демонстрация"] }, "response": { "questions": [ … ] } }` и возвращает `{ "id": "…", "status": "validated", "total": 3 }`. Идентификаторы статей и версий здесь — UUID, **не целочисленные `page_ids`**. Возможен `warning`, если количество не совпало с запрошенным. Тело запроса ограничено 512 КиБ; превышение возвращает HTTP 413 без чтения тела и записей. Применяется существующая схема v4 + миграции 03–07, новой миграции нет.

Синтетический пример **только для ручной вставки**, после выбора подходящей опубликованной статьи в интерфейсе (не отправлять в ИИ):

```json
{"questions":[{"question":"Демо: выберите первый вариант","options":["Первый","Второй","Третий","Четвёртый"],"correct_answer":0},{"question":"Демо: исправьте индекс перед одобрением","options":["Первый","Второй","Третий","Четвёртый"],"correct_answer":99},{"question":"Демо: отклоните запись","options":["Первый","Второй","Третий","Четвёртый"],"correct_answer":2}]}
```

`GET /api/testing/imports/<id>` возвращает счётчики `total`, `pending`, `invalid`, `approved`, `rejected`, `status`, исходный `payload` и страницу `items` (до 50). Для этого вида `payload.kind = "generated_response_v1"`, `payload.source.provenance = "selection_only"`: **источник выбран оператором, принадлежность вопроса содержимому статьи моделью не доказана**. `payload.response` хранит исходный ответ, `items[].payload` — исходную запись, `items[].edited_payload` — отдельную правку; все ответы изначально `invalid`, пока не выбран действующий код компетенции. Ошибочный индекс дополнительно требует исправления ключа. После сохранения и повторной проверки строка становится `pending`; одобрение требует `source_confirmed: true`, тогда создаётся утверждённый вопрос с вариантами и ключом в ревизии №1. Отклонение с причиной вопроса не создаёт. Сотрудник/руководитель не получают список импортов, карточку и ключ ответа; банк ответственного и старый файловый JSON-импорт продолжают работать.

Изолированная проверка 2026-11-10 (ранее, без рабочей БД): PostgreSQL 16, свежие `kb_it_*` БД через SSH-туннель на localhost. Файловый + ручной импорт **4/4**; общий PG lifecycle **12/12**; конкуренция **1/1 + 1/1**. Повторный офлайн-прогон без `DATABASE_URL`: Python **176 обнаружено / 161 успешно / 15 пропущено** (PG opt-in); Node `--experimental-vm-modules`: **74/74**.

Реальный Chromium/Playwright на dev: вход сотрудника демонстрационного отдела (активен в отделе DEMO, редактор пространства DEMO) → **создана одна новая исключительно синтетическая статья** «[синтетическая статья]» (UUID `[UUID синтетической статьи]`), черновик v1 → отправка на модерацию → администратора демонстрационного стенда одобрил **только заявку этой статьи** → опубликована v1. Пространство `internal`, для статьи нет `page_permissions`, автор в отделе DEMO; ответственного КК демонстрационного отдела видит её в `source-pages` и может прочитать. Поиск ограничен **отделом автора статьи**, а не только доступностью пространства: статья администратора без подразделения не подходит. Действующие или чужие статьи не трогали; ACL не расширяли.

В роли ответственного КК демонстрационного отдела в реальном браузере выбрана именно эта статья, зафиксирована текущая ревизия, указаны `questions_count=3`, `answers_count=4`, темы `["инструкции"]`, вручную вставлен **только синтетический JSON** с тремя вопросами (в первом `correct_answer=99`, в остальных допустимый индекс). Создан ровно один импорт `[UUID синтетического импорта]`: сначала все 3 записи `invalid` из-за отсутствующего кода компетенции, первая дополнительно из-за индекса вне диапазона. В UI первой записи выбран действующий код активной карты DEMO `SAFE`, явно отмечен ровно один правильный вариант и сохранены правки; второй назначен тот же код и сохранён; обе стали `pending`, исходные записи и `payload.response` **не изменились**. Одобрение без подтверждения источника не прошло; после личной сверки установлено явное подтверждение у каждой записи, обе одобрены. Третья запись отклонена с синтетической причиной. Итог импорта `processed`: **2 approved, 1 rejected, 0 pending/invalid**; в банке ровно два новых утверждённых вопроса с четырьмя вариантами каждый, привязанных к этой статье и её ревизии. После перезагрузки браузера карточка сохранила `provenance: selection_only` и исходный ответ: это **не свидетельствует о том, что LLM читала статью**.

Роли руководителя и сотрудника демонстрационного отдела: HTTP **403** для поиска источников, списка и карточки импорта. В Playwright не было запросов к сторонним адресам или внешней LLM; реальный текст компании не отправляли. Снимок до приёмки совпал с защищённым бэкапом предыдущего этапа (944 бизнес-строки в 56 таблицах, технические сессии исключены).
