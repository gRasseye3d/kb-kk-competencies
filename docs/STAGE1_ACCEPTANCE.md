# Stage1 — приёмка

Следующий этап запускается только после подтверждения пользователя.

- [ ] Сотрудник может отправить частично заполненный или полностью пустой тест. Неотвеченные вопросы учитываются как неверные, знаменатель сохраняется. При одном верном из двух — уровень 1; при нуле — уровень 0. Отправка окончательна, повтор запрещён.
- [ ] Руководитель обязан указать будущий срок назначения. Пустая UI-форма не отправляет запрос, прямой API-запрос без срока получает 400.
- [ ] Старое назначение руководителя без срока нельзя начать; показывается сообщение обратиться к руководителю. Миграция/автоматическое исправление старых данных не выполняется.
- [ ] Employee не видит историю даже своей редактируемой статьи; GET history и restore запрещены (403).
- [ ] История доступна разрешённым ролям с доступом к статье; восстановление дополнительно требует права редактирования. Admin restore добавляет новую ревизию, прежние не перезаписывает.

Для smoke используйте новые уникальные сущности и опубликованные тесты с непересекающимися компетенциями. Прохождение расходует попытку и включает cooldown — не используйте чужие назначения и не сбрасывайте результаты. Перед dev deploy сохраните защищённый backup и контрольные суммы существующих бизнес-строк. Конфигурацию целевого окружения не заменяйте локальной конфигурацией экспорта.

Фактический dev smoke 2026-11-08: два UI-прохождения (2 верных + 2 пустых; 4 пустых), требование срока, запрет истории employee, admin UI restore и read-only история manager/admin — успешны; неожиданных JS/HTTP-ошибок нет. Существующие бизнес-строки сохранены. Локально Python 121 passed + 2 opt-in skipped, frontend 30/30; отдельный изолированный PG-прогон 5/5 без skips.
